# Telegram-бот онлайн-записи

Бот для барбершопа, салона или студии: клиент сам выбирает услугу, день и свободное время, администратор получает уведомление. Двойная запись на один слот исключена на уровне базы данных.

## Возможности

**Для клиента**
- Пошаговая запись на inline-кнопках: услуга, день, свободное время, имя, телефон, подтверждение
- Кнопки «← К услугам» и «← Другой день» для возврата на шаг назад, `/cancel` или слово «отмена» прерывают запись
- Телефон одной кнопкой (`request_contact`) или вручную; номер проверяется и приводится к виду `+7 999 123-45-67`
- Прошедшее время, слоты ближе чем через 30 минут и занятые слоты не показываются; длительность услуги учитывается, так что 90-минутная запись занимает и следующий час
- «Мои записи»: список будущих записей с кнопкой отмены
- Разделы «Услуги и цены» и «Контакты» в главном меню

**Для администратора**
- Уведомления о новых записях и об отменах клиентами
- `/today` и `/week`: расписание на сегодня или на 7 дней, сгруппированное по дням
- `/drop <номер>`: отменить запись, клиенту придёт сообщение с телефоном студии

## Стек

Python 3.10+, aiogram 3 (FSM, CallbackData), SQLite (`sqlite3`), python-dotenv, Docker.

## Как запустить

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
python bot.py
```

Переменные в `.env`:

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather (обязательно) |
| `ADMIN_IDS` | Telegram ID администраторов через запятую |
| `TIMEZONE_OFFSET` | смещение часового пояса в часах, по умолчанию `3` (МСК) |
| `DB_PATH` | путь к файлу базы, по умолчанию `bookings.db` |

Через Docker (база в смонтированной папке, чтобы не терялась при пересоздании контейнера):

```bash
docker build -t booking-bot .
docker run -d --env-file .env -v "$(pwd)/data:/app/data" -e DB_PATH=/app/data/bookings.db booking-bot
```

В GitHub Actions (`.github/workflows/tests.yml`) на Python 3.11 и 3.12 проверяются компиляция и импорт модулей и запускаются тесты слоя БД (`pytest`). Локально: `python -m pytest -q`.

## Настройка

Всё в `config.py`, класс `Config`:
- `services`: список услуг (код, название, цена, длительность в минутах)
- `work_start` и `work_end`: первый слот и конец рабочего дня (запись должна закончиться не позже `work_end`)
- `days_ahead`: на сколько дней вперёд открыта запись
- `business_name`, `address`, `phone`: данные для раздела «Контакты»

## Структура проекта

```
bot.py        # точка входа: проверка токена, команды бота, polling
config.py     # настройки из .env и список услуг
db.py         # SQLite: создание таблицы, слоты, записи, отмена
keyboards.py  # reply- и inline-клавиатуры, классы CallbackData
handlers.py   # сценарии клиента и администратора
tests/        # pytest-тесты слоя БД
```

## Как это устроено

- Частичный уникальный индекс `ON bookings(date, time) WHERE status = 'active'` не даёт записать двоих на одно время, даже если они подтвердили одновременно; ошибка `IntegrityError` превращается в `SlotTakenError`, и клиент видит понятное сообщение.
- Свободный слот считается по пересечению интервалов: `[начало, начало + длительность)` новой записи не должен пересекаться ни с одной активной записью дня и выходить за конец рабочего дня. При сохранении эта проверка повторяется внутри транзакции `BEGIN IMMEDIATE`.
- Свободное время проверяется дважды: при выборе слота и при подтверждении записи.
- Шаги записи реализованы через `StatesGroup` aiogram 3, данные шага хранятся в контексте FSM.
- Время в callback data передаётся как `HH-MM`, потому что двоеточие зарезервировано разделителем `CallbackData`.
- Отменённые записи не удаляются, а получают статус `cancelled`; клиент может отменить только свою запись.
- Админские команды фильтруются по `ADMIN_IDS` прямо в декораторе обработчика.
